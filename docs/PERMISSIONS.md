# Permissions

Rowlio asks for the minimum Chrome will let it work with. The production manifest is
generated by `scripts/build.mjs` and checked by an automated test
(`tests/e2e/manifest.spec.ts`).

## Requested at install time

| Permission | Why it is needed | What it does *not* allow |
|---|---|---|
| `activeTab` | Gives Rowlio temporary access to the tab you invoke it on — by clicking the toolbar icon or using one of its keyboard shortcuts. This is how Rowlio reads a page. | Access to any other tab, to pages you did not invoke it on, or to your browsing history. The grant ends when the tab moves to another site or closes. |
| `scripting` | Lets Rowlio inject its content script (`content.js`, bundled in the extension) into that tab with `chrome.scripting.executeScript`. | Running remote code: only the bundled file is injected. |

Neither permission triggers an install warning in Chrome.

**No host permissions** (`host_permissions`) are requested, and **no content scripts are
declared** in the manifest, so Rowlio has no standing access to any website and none of
its code runs on pages you have not invoked it on.

## Requested only when you ask (optional)

| Permission | When Chrome asks | Why |
|---|---|---|
| `optional_host_permissions`: `http://*/*`, `https://*/*` | Only when you press **Grant access to *site*** or **Always allow on *site*** in the workspace. Rowlio requests exactly one origin (for example `https://example.com/*`), and Chrome shows its own confirmation prompt. | Convenience: keep access to a site you use often without clicking the icon each time (for example after restarting the browser). |

The broad patterns in the manifest only define what *may* be requested; nothing is
granted until you approve a specific site. Granted sites are listed under
**Settings → Site access**, where each can be removed.

## Not requested

| Permission | How Rowlio works without it |
|---|---|
| `storage` | Settings, projects and recipes are kept in IndexedDB, which needs no permission. |
| `downloads` | Exports are saved with an ordinary download link (`<a download>`). |
| `clipboardWrite` | Copy uses the standard clipboard API in response to your click. |
| `tabs` | Tab titles and URLs are visible only for the tab you granted access to; that is all Rowlio needs. Batch URLs changes the address of that one connected tab with `chrome.tabs.update`, which needs no permission. |
| `webNavigation`, `webRequest`, `cookies`, `history`, `bookmarks`, `alarms`, `notifications`, `identity`, `nativeMessaging`, `debugger`, `unlimitedStorage` | Not used. |

Version 1.1.0 added features (batch URLs, contacts, file import, new exports, sound and
motion) **without adding any permission**.

## Other manifest entries

- `content_security_policy.extension_pages`: `default-src 'self'; script-src 'self';
  style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; font-src 'self';
  connect-src 'self'; worker-src 'self'; object-src 'none'; base-uri 'none';
  form-action 'none'; frame-ancestors 'none'`. Stricter than Chrome's default: extension
  pages cannot connect to, or load anything from, a remote server. (`'unsafe-inline'`
  applies to *styles* only, for element sizes in the data grid; scripts are never inline.)
- `commands`: three keyboard shortcuts. A shortcut counts as invoking the extension, so it
  grants `activeTab` for the current tab exactly like a click.
- No `externally_connectable`, no `web_accessible_resources`: web pages cannot message the
  extension or load its files.
- `homepage_url`: the Unique Labs website, shown by Chrome on the extension's details
  page.
- `minimum_chrome_version`: 120.

## Text for the Chrome Web Store "permission justification" form

- **activeTab** — "Rowlio reads the current page only after the user clicks the extension
  or uses its shortcut, in order to extract the tables, lists, links, images or metadata
  the user asks for."
- **scripting** — "Used to inject the extension's own bundled content script into the tab
  the user invoked Rowlio on. The script performs the extraction locally in the page. No
  remote code is loaded or executed."
- **Optional host permissions** — "Requested at runtime for a single site, only when the
  user chooses 'Grant access' or 'Always allow on this site', so that Rowlio keeps working
  on that site without a new click. Never requested automatically."
- **Remote code** — "No. All code is contained in the package."
- **Data usage** — "Rowlio does not collect or transmit any user data. All processing and
  storage is local to the user's device."

## The test build

`npm run build:e2e` writes a separate build to `dist-e2e/` that adds host permissions for
`http://127.0.0.1/*` and `http://localhost/*` so automated tests can reach the local
fixture site without a toolbar click, and opens the in-page shadow root so tests can
operate the visual selector. `npm run package` refuses to package a build that contains
host permissions. The production build is additionally tested with real toolbar clicks
(`tests/e2e/production.spec.ts`).
