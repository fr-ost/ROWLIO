Two of the most common extraction jobs need no setup at all: listing every link on a page and listing every image. They are useful for auditing a site, collecting sources for research, checking a page before it is published or gathering addresses for a later step. This guide shows how to do both and explains the details that decide whether the list is correct.

Extracting links

With Rowlio, open the page, click the icon and choose Links. Each link becomes a row with its text, its full address, the address exactly as written in the page, and attributes such as title, target and rel.

A typical page has far more links than you expect: navigation, footers, social buttons, "skip to content" anchors. The value is in filtering.

  • Internal or external. Internal links point to the same site. External ones leave it. An audit of outbound references needs only the second group.
  • Inside a container. Limit the extraction to the article body or the results list and the navigation disappears.
  • Text contains. Keep only links whose text includes a word, such as "PDF" or "Download".
  • Matching a selector. For precise control, give a selector such as a[href$=".pdf"] for links that end in .pdf.
  • Skip duplicates. The same address is often linked from a title, a thumbnail and a "Read more".

Relative and absolute addresses

Pages rarely write full addresses. A link is more often /products/42 or ../about, which only makes sense relative to the page it is on. A list of such fragments is useless once it leaves the page, so an extractor must resolve each one to a full address such as https://shop.example/products/42.

Two details are easy to get wrong. A page can declare a different starting point with a <base href> tag, and every relative link must be resolved against that instead of the page address. And some "links" are not addresses at all: mailto:, tel: and javascript: entries should be recognised for what they are and never treated as pages to visit.

What link data is good for

  • Finding broken or outdated references in your own pages before readers do.
  • Collecting sources from a long article or a bibliography page.
  • Reviewing rel attributes such as nofollow and sponsored across a page.
  • Building a list for a second step. Extract the product links from a category page, then run a batch over those addresses to collect details from each product page.

Extracting images

Choose Images and each image becomes a row: its address, alternative text, title, width and height, the kind of element it came from, and any other candidate sources. Rowlio lists addresses. It does not download the image files.

Images are less straightforward than links, because modern pages rarely use one plain image tag.

Responsive images

A single picture is often offered in several sizes through the srcset attribute or a <picture> element, and the browser picks one to suit the screen. If you only read src, you may get a small placeholder. A good extractor reads the candidates and reports the best one along with the alternatives.

Lazy loading

To load faster, many pages put the real address in an attribute like data-src and fill in src only when the image scrolls into view. Until then src is empty or a tiny blank. Extractors need to check these attributes, or half the images on a long page come back as placeholders. If results still look incomplete, scroll through the page once and extract again.

Background images

Banners and tiles are frequently set as CSS backgrounds, so they are not image elements at all. They are found only if the tool also inspects styles, which is slower and usually offered as an option.

Filtering images

An unfiltered list is mostly icons, tracking pixels and logos. Useful filters:

  • Minimum width and height. Setting both to 200 pixels removes icons and spacers in one step.
  • Inside a container. Restrict to the gallery or the article.
  • Address contains. Keep only images from a certain folder or of a certain type.
  • Skip duplicates.

What image data is good for

  • Accessibility checks. Sort by the alternative-text column and every image without a description is at the top.
  • Performance reviews. Oversized images stand out when width and height are listed side by side.
  • Catalogue work. Match product image addresses to product rows.

A note on rights

A list of addresses is a set of facts about a page. The images themselves usually belong to someone, and so do the articles behind the links. Listing them for an audit or for research is very different from copying and republishing the content. Is web scraping legal? goes through the questions worth asking first.
