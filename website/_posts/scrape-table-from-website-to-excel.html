A table on a web page looks like a spreadsheet, so it is natural to expect that moving it into Excel takes one step. Often it does not. Merged cells shift columns, numbers arrive as text, and the table you wanted turns out to be split over several pages. This guide covers three ways to do it, when each one works, and how to deal with the usual problems.

Method 1: copy and paste

Select the table with the mouse, copy it, and paste it into a sheet. For a small, simple table this is the fastest route and there is no reason to use anything else.

It breaks down in predictable ways:

  • Formatting comes along. Fonts, colours, links and images are pasted too. "Paste special → Text" helps, but then merged cells collapse.
  • Selecting is fiddly. On long or scrollable tables it is easy to miss the last rows or pick up text around the table.
  • Hidden rows are unpredictable. Rows hidden by a filter on the page may or may not be copied, and you get no warning either way.

Method 2: Excel's "From Web" import

Excel can fetch a page itself: Data → Get Data → From Other Sources → From Web. You paste the address, Excel lists the tables it found, and you load one. The import can be refreshed later, which is useful for a table that changes daily.

The limitation is that Excel downloads the page on its own, without your browser. It therefore cannot see:

  • pages behind a login you are signed in to in the browser;
  • tables that are built by JavaScript after the page loads, which is how many modern sites work;
  • whatever you filtered, sorted or expanded on the page before importing.

If the list of tables comes back empty for a page where you can plainly see one, this is the reason.

Method 3: a table extractor in the browser

A browser extension reads the page as your browser has rendered it, so it sees the same table you see, including ones created by scripts. With Rowlio the steps are:

  1. Open the page and click the Rowlio icon in the toolbar.
  2. Choose Extract tables. Every table on the page is listed with a preview and its row and column counts.
  3. Extract the one you want, check it in the data preview, and choose Export → Excel (XLSX).

The file is built in your browser. Nothing is uploaded, which matters if the table is on an internal or signed-in page.

Problems you will run into, and what to do

Merged cells

Web tables use rowspan and colspan to merge cells. When a merged cell is flattened carelessly, every value to its right moves one column left. A proper extractor rebuilds the grid first and then either repeats the merged value in each cell it covers or leaves the covered cells empty. Repeating is usually what you want for analysis, because every row then stands on its own when you sort or filter.

Headers that span two rows

A header such as "2024" above "H1" and "H2" should become two columns named "2024 - H1" and "2024 - H2". If your import shows the second header row as the first row of data, promote it manually or use a tool that merges header rows.

Numbers stored as text

Values like 1,234.50, € 12 or 15% are text until something converts them. In Excel, select the column and use Data → Text to Columns → Finish, or clean the column before exporting. Be careful with identifiers: a product code like 00123 or a phone number should stay text, or the leading zeros are lost.

Dates in the wrong order

03/04/2024 is 3 April in most of the world and 4 March in the United States. Excel guesses from your system settings. If you can, convert dates to the unambiguous 2024-04-03 form before they reach the spreadsheet.

The table continues on the next page

Copying page by page is slow and error-prone. See how to collect data across pages and infinite scroll for doing it in one run with sensible limits.

A quick check before you trust the result

Whatever method you use, compare three things with the page: the number of rows, the first row and the last row. Then sort one numeric column and look at both ends. Text hiding among numbers shows up immediately, and it takes less than a minute.
