CSV is the most widely accepted data format there is. Every spreadsheet, database and analysis tool reads it. It is also the format people most often open and find broken: strange characters, everything in one column, phone numbers turned into scientific notation. Almost all of these problems come from how the file is opened, and all of them are avoidable.

What a CSV file actually is

A CSV file is plain text. Each line is a row, and a delimiter, usually a comma, separates the values:

Name,Price,City
"Tea, premium",12.50,Dhaka
Coffee,9.00,Lisbon

Two rules matter. A value that contains the delimiter, a quote or a line break is wrapped in double quotes, as in the first row above. And a quote inside a quoted value is written twice. Tools that follow these rules can exchange any text safely. Problems start when a file is written or read by something that ignores them.

Problem 1: broken characters

You export names like "Zoë" or "ঢাকা" and Excel shows "ZoÃ«" or a row of symbols. The file is fine. It is encoded as UTF-8, which is the standard, but Excel assumed an older regional encoding when you double-clicked it.

The fix is a three-byte marker at the start of the file called a BOM. It tells Excel "this is UTF-8". Rowlio adds it by default. If you receive a file without one, import it through Data → From Text/CSV and choose "65001: Unicode (UTF-8)" as the file origin.

Problem 2: everything lands in one column

In many European and other locales the comma is the decimal separator, so Excel there expects a semicolon between values. A comma-separated file then opens as one wide column.

Either export with a semicolon delimiter if the file is meant for Excel in such a locale, or import the file through Data → From Text/CSV, where you can choose the delimiter yourself. For exchange between programs, stay with the comma.

Problem 3: values that change by themselves

Spreadsheets try to be helpful and convert text that looks like something else:

In the fileWhat Excel may showWhy
00123123Treated as a number
88017123456788.80171E+12Long number shown in scientific notation
3-43 AprilLooks like a date
1E5100000Scientific notation

The CSV format has no way to say "this column is text". You have two options. Import through Data → From Text/CSV and set the column type to Text, or export to XLSX instead, where each cell carries its type and identifiers stay exactly as written.

Problem 4: a file that runs formulas

A cell that starts with =, +, - or @ can be treated as a formula when the file is opened. With scraped data, that text came from a web page you do not control. This is a real security issue called CSV injection, and a careful exporter neutralises such cells. CSV formula injection explained has the details.

CSV or something else?

  • CSV when another program will read the data, or when you want the simplest possible file.
  • Excel (XLSX) when a person will open it in a spreadsheet. Types, Unicode and several sheets all work without import steps.
  • JSON when a developer or an API will consume it.

A checklist for a clean CSV

  • UTF-8 with a BOM if Excel will open it.
  • The delimiter matches the reader's locale, or you import instead of double-clicking.
  • Identifiers, postcodes and phone numbers are imported as text.
  • Formula-like cells are protected.
  • The header row is present and the column names are meaningful.
  • Row count in the file equals the row count you extracted.

With those six points covered, a CSV behaves the same wherever it goes.
