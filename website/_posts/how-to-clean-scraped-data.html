Data taken from a web page is written for people to read, and it shows. Prices carry currency symbols, names have stray spaces, the same item appears twice, and a date is written three different ways. Cleaning is what turns that into something you can sort, total and trust. The order of the steps matters, because some fixes only work after others. This is the order that causes the least rework.

Before you change anything

Keep the original. Every cleaning step is a decision, and some of them will be wrong. Work in a tool that lets you undo each step and return to the data as extracted. In Rowlio the original extraction is always kept, every operation can be undone, and each one reports how many cells it changed, so a step that touched 4,000 cells when you expected 40 is noticed at once.

Then look at the shape of the data: how many rows and columns, which columns have empty cells, and what kind of values each column holds. A column summary showing the count of distinct values and the most frequent ones reveals most problems before you start.

Step 1: trim and normalise whitespace

Web text is full of invisible characters: leading and trailing spaces, line breaks inside a cell, runs of several spaces, non-breaking spaces. They make "Dhaka" and "Dhaka " different values, which breaks every later step that compares cells.

Do this first, on every column. Trim the ends and collapse runs of whitespace into a single space.

Step 2: remove empty rows and columns

Spacer rows, advertising slots and decorative columns often come along with the real content. Remove rows and columns that are entirely empty. Be more careful with rows that are only partly empty: a product without a rating is still a product.

Step 3: remove duplicates

Duplicates come from promoted items repeated on each page, from listings that shifted while you were collecting, and from overlapping runs. Remove them after whitespace is fixed, or near-identical rows will be missed.

Think about what makes two rows the same. Rows identical in every column are safe to remove. Rows that share an address or a product ID but differ elsewhere need a decision about which one to keep.

Step 4: split what is combined

One cell often holds several facts: "Lisbon, Portugal", "4.5 (128 reviews)", "Size: M / Colour: Blue". Split by the delimiter into separate columns, or pull out one part with a pattern. A regular expression such as (\d+) reviews extracts the review count and leaves the rest alone.

Do this before converting numbers, so each new column holds one kind of value.

Step 5: convert numbers

A price like $1,299.00 is text until the symbol and the thousands separator are removed. Three things to watch:

  • Decimal conventions. 1.299,00 is the same amount written the European way. A converter has to recognise both.
  • Digits in other scripts. ১২৫০ is 1250 in Bengali digits and should convert like any other number.
  • Things that only look like numbers. Postcodes, phone numbers and product codes are identifiers. Leave them as text, or 00123 becomes 123.

Afterwards, sort the column and look at both ends. Leftover text sorts to one end and is easy to spot.

Step 6: standardise dates

Convert dates to the ISO form 2024-04-03. It sorts correctly as text and is read the same way everywhere.

The trap is ambiguity. 03/04/2024 is 3 April or 4 March depending on the country, and nothing in the value tells you which. A careful tool converts only unambiguous dates, such as 3 April 2024 or 25/12/2024, and leaves the doubtful ones untouched and counted. Check how the source site writes dates, then deal with the rest deliberately.

Step 7: make text consistent

Categories typed by people vary: In stock, in stock, IN STOCK. Pick one form and apply it with a case conversion or find and replace. Normalise addresses in a URL column as well, so the same link is not counted twice because of a trailing slash.

Where a value is shown only once for a group, with empty cells beneath it, use fill down so that every row carries its own value.

Step 8: name and order the columns

Rename columns to say what they contain: price_usd tells the next reader more than Text 3. Put identifying columns first and delete helper columns you no longer need.

The final check

  • Row count: does it match what the site showed, minus the duplicates you removed?
  • Empty cells: is each one a true absence, or a value the extraction missed?
  • Numeric columns: do the minimum, maximum and average look plausible?
  • Spot check: compare three random rows with the live page.

Then export. If the file is going to a spreadsheet, exporting to CSV correctly covers encoding, delimiters and identifiers, and formula injection explains why some cells need protecting.

Make it repeatable

If you will collect the same data again next month, write down the steps you applied, in order. Cleaning done the same way each time is what makes two months of data comparable.
