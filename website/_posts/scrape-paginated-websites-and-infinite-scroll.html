The data you want is rarely on one page. A catalogue has forty pages, a feed keeps loading as you scroll, a directory hides the rest behind a "Load more" button. Collecting it all is the same extraction repeated, plus a way to move forward and a clear rule for when to stop. This guide covers each kind of paging and the limits that keep a run under control.

The four kinds of paging

TypeHow to recognise itHow to move on
Next link"Next", "›" or "Older posts" at the bottomFollow the link until it disappears
Page numbers1 2 3 … 40Go to the number after the current one
Load moreA button that adds items to the same pageClick it until it is gone
Infinite scrollNew items appear as you reach the bottomScroll, wait, repeat

The first two replace the page content. The last two add to it. That difference decides how the data has to be collected.

Next links and page numbers

This is the simplest case. Extract the current page, activate the next control, wait for the new content, extract again. In Rowlio you set up the extraction on the first page and then open Pagination. The next-page control is detected automatically from signals such as rel="next", the link text and its label. If the detection picks the wrong element, you can point at the right one or type a selector for it.

Some sites load the next page without a full reload: the address changes, the list is swapped, and the rest of the page stays. From the outside this works the same way. The run waits until the content has actually changed before reading it.

Infinite scroll and load-more buttons

Here the page grows. Two details matter.

First, collect while scrolling, not at the end. Many feeds keep only the items near the screen in the page and remove the earlier ones to save memory. If you scroll to the bottom and extract once, you get the last fifty items instead of all two thousand.

Second, wait for content, not for time. After each scroll the page needs a moment to fetch and render. A fixed pause is either too short on a slow connection or wastefully long. A good run watches the page and continues when new items have appeared, or gives up after a timeout.

Always set limits

A run without limits is a crawler, and a crawler pointed at the wrong page can keep going for hours. Decide the bounds before you press start.

  • Maximum pages or scrolls. Start with three. If the result looks right, raise it.
  • Maximum records. If you need the first 500 results, say so and stop there.
  • Delay between pages. A second or two is considerate and costs you little.
  • A time limit for scrolling, so a feed that never ends cannot run forever.

Rowlio requires these limits for every run and shows a Stop button in the workspace and on the page itself. Stopping keeps everything collected so far.

How a run should end

You should always know why a run stopped. The honest reasons are:

  • there was no next page, so everything was collected;
  • a limit you set was reached;
  • you pressed Stop;
  • the next page returned the same records as the previous one, which means the site is looping;
  • scrolling stopped producing new items.

If a tool reports only "done", you cannot tell a complete result from a truncated one. Check the stated reason and compare the record count with what the site says it has.

Duplicates across pages

Listings change while you collect. A new item is added at the top, everything shifts down by one, and the last item of page two appears again as the first item of page three. Promoted items are often repeated on every page as well. Remove duplicate rows after the run, and decide what "duplicate" means: the same address or product ID is a better test than every column being identical.

When you already have the addresses

Sometimes there is no "next" at all. You have a list of pages, for example the product links you extracted from a category page, and you want details from each one. That is a batch run: the same extraction applied to each address in a list you supply, with the same limits, delay and Stop button. Each row records the page it came from, so you can join the details back to the original list.

A sensible routine

  1. Get the extraction right on one page first.
  2. Run with a limit of two or three pages and inspect the result.
  3. Check for duplicates and for a page that came back empty.
  4. Only then raise the limit to what you need.
  5. Note the stop reason and the date with the saved data.

Before collecting at any volume, read what to check about a site's rules. When the run is finished, cleaning the data is the next step.
